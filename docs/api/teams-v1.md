# 팀·초대·프로젝트 공유 API v1

관련 이슈: #27 (후속 #54·#55 팀 사무실 화면·실시간 범위, #197 팀원별 공유 범위·폴더 이름 프로젝트)

모든 경로는 `/api/v1` 아래이고 세션 쿠키가 필요하며, 쓰기 요청은 CSRF 토큰이 필요합니다.

## 권한 원칙

- 팀 권한은 팀 역할(`OWNER`·`MANAGER`·`MEMBER`)로만 정합니다. 인스턴스 역할(`SUPER_ADMIN`·`ADMIN`)은 팀 권한을 주지 않습니다.
- 내가 속하지 않은 팀은 없는 팀과 같은 `404 not_found`입니다. 속해 있지만 권한이 모자라면 `403 forbidden`입니다.
- 팀마다 `OWNER`는 정확히 한 명입니다(DB 부분 고유 인덱스 + 커밋 시점 트리거).
- 구성원 목록에는 표시 이름·역할·합류 시각만 나오고 이메일은 나오지 않습니다.

| 동작 | OWNER | MANAGER | MEMBER |
|---|---|---|---|
| 팀 보기·공유 프로젝트 보기 | ✓ | ✓ | ✓ |
| 팀 이름·설명 수정 | ✓ | ✓ | |
| 초대 | MANAGER·MEMBER | MEMBER만 | |
| 초대 목록·취소 | ✓ | ✓ | |
| 역할 변경(MANAGER↔MEMBER) | ✓ | | |
| 내보내기 | 누구나(본인 제외) | MEMBER만 | |
| 탈퇴 | 이전 후에만 | ✓ | ✓ |
| 소유권 이전 | ✓ | | |
| 팀 삭제 | ✓ | | |

## 엔드포인트

| 요청 | 설명 |
|---|---|
| `POST /teams {name, description, share_mode}` | 만든 사람이 OWNER. 사용자당 소속 팀 50개까지. `share_mode` 생략 시 `all`(#197) |
| `GET /teams` | 내 팀과 내 역할·내 공유 범위(`share_mode`) |
| `PUT /teams/{id}/share-mode {share_mode}` | 내가 이 팀에 보여 줄 범위 변경(본인만, 모든 역할). 즉시 반영(#197) |
| `GET /teams/{id}` / `PATCH` / `DELETE` | 상세(구성원 포함)·수정·삭제 |
| `PATCH /teams/{id}/members/{user_id} {role}` | MANAGER·MEMBER로만. OWNER 지정은 `409 use_transfer` |
| `DELETE /teams/{id}/members/{user_id}` | 내보내기 또는 본인 탈퇴. OWNER 탈퇴는 `409 owner_must_transfer` |
| `POST /teams/{id}/transfer {user_id}` | 대상 구성원이 OWNER, 이전 OWNER는 MANAGER |
| `POST /teams/{id}/invitations {email, role}` | 7일 유효 초대. `{id, email, role, expires_at, invite_url, mailed}` |
| `GET /teams/{id}/invitations` / `DELETE …/{invitation_id}` | 열린 초대 목록·취소 |
| `POST /invitations/accept {token, share_mode}` | 초대받은 이메일로 로그인한 사용자만 수락. 실패는 모두 `400 invalid_token`. `share_mode` 생략 시 `all`(#197). 이미 구성원이면 기존 범위를 바꾸지 않음 |
| `POST /projects {display_name}` / `GET /projects` | 내 프로젝트(`origin`: `manual`·`workspace`)와 공유한 팀 |
| `PUT` / `DELETE /projects/{id}/shares/{team_id}` | 프로젝트 소유자가 자신이 속한 팀에만 공유·공유 해제 |
| `GET /teams/{id}/projects` | 이 팀에 보이는 프로젝트(이름·소유자 표시 이름). 아래 공유 범위 규칙을 따름 |

## 초대

- 토큰은 SHA-256 해시만 저장하고 한 번만 쓸 수 있습니다. 같은 주소로 다시 초대하면 이전 초대는 취소됩니다. 이미 구성원이면 `409 already_member`입니다.
- 메일 설정이 있으면 초대 메일을 보내고(`mailed: true`), 없어도 응답의 `invite_url`을 초대한 사람에게 한 번 돌려주어 직접 전달할 수 있습니다.
- 링크는 `{기준 주소}/invite#token=…`입니다. 웹 `/invite` 화면은 토큰을 주소창에서 지우고 탭 저장소(sessionStorage)에만 잠시 둡니다.
- 가입 정책이 `INVITE_ONLY`이면 `POST /auth/signup`에 `invite_token`을 함께 보내고, 초대받은 이메일과 같아야 가입됩니다. 가입 후에도 이메일 확인과 로그인 후 수락이 필요합니다.

## 팀원별 공유 범위(#197)

구성원마다 팀별로 `share_mode`를 가집니다. 다른 구성원의 범위는 API로 나오지 않습니다(`GET /teams/{id}`의 `share_mode`는 내 것).

| 값 | 팀 사무실에 보이는 내 세션 | 팀에 보이는 내 프로젝트 이름 |
|---|---|---|
| `all`(모두 공유) | 폐기되지 않은 내 장치의 모든 세션. 프로젝트가 없으면 화면에 "(이름 없음)" | 내 모든 프로젝트 |
| `selected`(선택한 프로젝트만) | 이 팀에 공유한 내 프로젝트의 세션만(#54 규칙) | 이 팀에 공유한 프로젝트만 |
| `none`(공유 안 함) | 없음 | 없음 |

- **새 구성원·새 팀**: 웹의 팀 만들기·초대 수락 화면에 "이 팀에 내 작업을 모두 공유"가 미리 체크되어 있고, 보이는 것("팀원에게 보이는 것: 상태·활동 종류·표시 이름·프로젝트 이름. 대화·코드·경로·폴더 전체 경로는 보이지 않음")을 함께 보여 줍니다. 체크한 채 제출하면 `all`(동의), 끄면 `selected`를 명시적으로 보냅니다. API에서 생략하면 `all`입니다.
- **기존 구성원**: 마이그레이션 `0009`가 `selected`로 채워 지금까지의 화면(공유한 프로젝트만)이 그대로입니다. `/teams` 화면에서 바꿉니다.
- 범위를 바꾸면 팀 사무실 스냅샷·실시간(다음 주기)·상세·타임라인이 바로 그 범위로 다시 걸러집니다. `selected`로 돌아오면 전에 체크해 둔 프로젝트 공유가 다시 쓰입니다(범위를 바꿔도 공유 체크는 지우지 않음).
- 범위 변경은 감사 로그 `team.share_mode_changed`(`details.reason`: `이전_to_새값`, 예 `selected_to_all`)로 남습니다. 같은 값은 기록하지 않습니다. 팀 만들기·합류 로그(`team.created`·`team.joined`)의 `details.reason`에 `share_all` 같은 처음 범위를 남깁니다.
- 어떤 범위든 장치 이름(PC 이름)은 소유자 표시 이름으로 바뀌고, 세션의 `workspace_name`은 팀 화면에서 `null`입니다. 다만 폴더 이름으로 자동 만든 프로젝트의 **이름**은 그 프로젝트가 팀에 보이면(`all`이거나 `selected`로 체크) 프로젝트 이름으로 보입니다.

## 폴더 이름 프로젝트 자동 생성(#197)

- 이벤트에 `workspace_name`(PC별 동의 시에만 옴, #181)이 있으면 서버가 장치 소유자의 프로젝트 중 그 이름과 같은 표시 이름의 프로젝트(가장 먼저 만든 것)를 찾고, 없으면 `origin: "workspace"`로 만듭니다. 소유자별로 이름당 하나이고 동시 요청은 advisory lock으로 직렬화합니다. 같은 이름의 수동 프로젝트가 있으면 그것을 씁니다.
- 세션이 직접 정한 배정(`PUT /office/sessions/{id}/project`, `project_manual`)이 없으면 그 프로젝트에 넣습니다. 폴더 이름이 바뀌면 새 이름의 프로젝트로 옮깁니다.
- 직접 정한 배정은 항상 우선합니다. "프로젝트 없음"을 직접 고른 것도 존중해 자동으로 다시 넣지 않습니다. 마이그레이션 `0009`는 이미 프로젝트가 있던 세션을 직접 정한 것으로 표시합니다.
- 폴더 이름이 없는 세션은 자동 프로젝트가 없습니다.

## 프로젝트 공유

- 공유는 프로젝트 소유자의 명시적 요청(동의)으로만 생깁니다. 다른 구성원은 남의 프로젝트를 공유할 수 없습니다. 프로젝트 공유 체크는 공유 범위가 `selected`일 때 쓰입니다.
- 공유를 해제하면 팀 목록과 팀 사무실에서 바로 사라집니다. 팀 사무실 표시 규칙은 `docs/api/office-live-v1.md`의 팀 사무실 절(#54·#55)입니다.
- 구성원이 팀을 떠나거나 내보내지면 그 사람이 이 팀에 공유한 프로젝트 공유도 함께 지워집니다.
- 프로젝트와 Collector 저장소의 연결(`project_sources` 지문)은 아직 수집 경로가 없습니다.

## 웹 화면(#52)

`/teams`(사무실 상단 "팀" 링크):

- 팀 만들기, 내 역할 표시, "팀 사무실 보기"(`/?team=<id>`)
- 구성원 표: OWNER는 역할 변경(관리자↔구성원)·내보내기·소유권 넘기기, MANAGER는 구성원만 내보내기. 할 수 없는 동작은 숨기고 서버가 최종 판단합니다.
- 초대: 이메일·역할(OWNER는 관리자도 가능). 메일 발송 여부와 함께 초대 링크를 보여 주고 복사할 수 있습니다. 열린 초대 목록과 취소.
- 팀 나가기(소유자는 숨기고 "소유권을 넘긴 뒤에 나갈 수 있습니다" 안내), 팀 삭제(소유자). 내보내기·나가기·이전·삭제는 확인 창을 거칩니다.
- 내 프로젝트와 공유: 프로젝트 만들기, 팀별 공유 체크, 열린 세션을 프로젝트에 넣기. 폴더 이름으로 자동 만든 프로젝트는 "폴더" 표시.
- 팀 만들기 아래와 `/invite` 수락 화면에 공유 동의 상자("모두 공유" 미리 체크 + 보이는 것 설명)(#197).
- 팀 카드마다 "이 팀에 보여 줄 내 작업": 모두 공유 / 선택한 프로젝트만 / 공유 안 함. "선택한 프로젝트만"이면 이 팀에 공유할 내 프로젝트 체크 목록(폴더 프로젝트 포함).

## 알려진 제한

- 실제 브라우저에서 화면 조작은 확인하지 않았습니다(헤드리스 브라우저 없음, #63). 권한 규칙과 경로는 단위 테스트로 확인했습니다.
- 감사 로그에는 사용자·팀 ID와 역할 이름만 남깁니다.
