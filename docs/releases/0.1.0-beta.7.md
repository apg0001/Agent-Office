# Agent Office 0.1.0-beta.7

> **상태: Beta.** Stable이 아닙니다. 아래 "검증하지 않은 것"은 지원한다고 하지 않습니다. 서버·웹 이미지는 GHCR `ghcr.io/apg0001/agent-office-server`·`agent-office-web` `0.1.0-beta.7`, Collector는 GitHub Release `collector-v0.1.0-beta.7`으로 냅니다.

대상: 0.1.0-beta.6 사용자와 새 설치자. **서버를 먼저 올리고 Collector를 나중에 업데이트합니다**(이전 서버는 새 이벤트 필드를 거부).

## 바뀐 것

| 영역 | 내용 | 이슈 |
|---|---|---|
| 승인 대기 종류 | 권한 승인(`✋ 승인 대기`, 머리 위 `!`), 질문·선택지(`❓ 질문 대기`, `?`), 계획 확인(`📋 계획 확인 대기`, `!`)을 머리 위·활성 세션 목록·상세·범례에 구분 표시 | #262 |
| 이벤트 계약 | `approval.requested`에만 붙는 선택 enum `wait_kind`(`permission`·`question`·`plan_review`). 도구 이름·질문 문장·계획 본문은 보내지 않음 | #262 |
| Collector(Claude) | `PermissionRequest`의 `tool_name`으로 종류 판별: `AskUserQuestion` → 질문, `ExitPlanMode`·계획 도구 → 계획 확인, 그 밖 → 권한. Codex는 항상 권한 | #262 |
| 서버 | DB 마이그레이션 0010 `agent_current_states.wait_kind`, 실시간 스냅샷 `agents[].wait_kind` | #262 |

## 실제로 검증한 것

| 항목 | 근거 |
|---|---|
| Hook 순서 | Claude Code 2.1.310 Linux arm64 대화형 TUI: 질문·계획 확인·권한 모두 `PreToolUse` → `PermissionRequest`(tool_name) → `Notification(permission_prompt)` |
| 서버·웹 | CI(`CI Gate`, 브라우저 E2E), 서버 pytest(PostgreSQL), Vitest, 합성 데모 스크린샷 |
| Collector | Go 단위 테스트, macOS·Windows·Ubuntu 러너 Core 스모크·설치 시험 |
| PWA(beta.6) | 소유자 iPhone에서 운영 주소 설치·접속 확인 |

## 검증하지 않은 것(지원한다고 하지 않음)

- macOS·Windows Claude Code의 같은 Hook 순서(Linux에서만 실측)
- Codex의 질문·계획 확인 구분(항상 권한으로 표시)
- Android·Windows·macOS 기기의 PWA 설치

## 알려진 위험

- 권한 요청을 거절하면 Claude가 이후 Hook을 보내지 않아 다음 프롬프트까지 승인 대기로 남습니다(실측, 이전과 같음).
- 서버보다 Collector를 먼저 올리면 승인 요청 이벤트가 거부됩니다. 서버를 먼저 올립니다.
- 코드 서명·공증 없음(소유자 결정으로 하지 않음).

## 호환성

| 구성 요소 | 값 |
|---|---|
| 이벤트 프로토콜 | `schema_version` `1.0`(선택 필드 `wait_kind` 추가) |
| DB 마이그레이션 | 0010(`agent_current_states.wait_kind`, NULL 허용, 기존 행은 NULL = 권한) |
| 서버 ↔ 웹 | 이전 웹은 `wait_kind`를 무시(모두 `✋ 승인 대기`) |
| 서버 ↔ Collector | 새 서버는 beta.2~beta.6 Collector와 동작. beta.7 Collector는 beta.7 이상 서버 필요 |
