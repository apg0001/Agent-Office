# 사무실 렌더러

관련 이슈: #45, #47, #48, #49 (후속 #46, #50, #51)

`apps/web/src/office`는 사실 상태를 받아 아이소메트릭 사무실을 그립니다. 논리와 투영, 사실과 연출을 분리합니다.

| 파일 | 역할 | Phaser 의존 |
|---|---|---|
| `types.ts` | 서버 스냅샷·증분(`docs/api/office-live-v1.md`)과 같은 사실 상태 타입, 데이터 출처(`server`/`synthetic`) | 없음 |
| `grid.ts` | 논리 그리드: 구역·가구·벽·출입구·책상 자리, 걷기 가능 판정 | 없음 |
| `iso.ts` | 그리드 ↔ 2:1 아이소메트릭 화면 투영, 깊이 정렬, 타일 마름모 | 없음 |
| `behavior.ts` | 활동 → 목적지 구역, 서버 책상 번호 → 자리, 업무석 줄 수, 목적지 칸 | 없음 |
| `synthetic.ts` | 서버 없이 개발하기 위한 결정적 합성 상태(`source: "synthetic"`) | 없음 |
| `liveStore.ts` | 서버 스냅샷·증분 병합. 같은 ID는 `change_seq`가 큰 갱신만 적용, 합성 상태에 섞지 않음(#47) | 없음 |
| `smoothing.ts` | 이벤트 폭주 병합: 표시 구역 변경에 최소 1.5초 체류, 승인 대기·유휴·종료는 즉시(#47) | 없음 |
| `liveSource.ts` | 로그인 세션이 있으면 `WS /api/v1/live` 연결·지수 백오프 재접속(최대 30초), 없으면 합성 | 브라우저 |
| `pathfinding.ts` | 4방향 A* 경로, 막힌 목적지는 가장 가까운 걸을 수 있는 칸으로(#49) | 없음 |
| `camera.ts` | 자동 초점·수동 조작 일시정지·줌 범위(0.5~2.5)·활동 캐릭터 중심(#49) | 없음 |
| `OfficeScene.ts` | Phaser 장면: 바닥·가구·구역 이름 그리기, 매 프레임 캐릭터 이동 | 있음 |
| `OfficeView.tsx` | React 컨테이너. Phaser를 브라우저에서만 지연 로드, 합성 데이터 배지 | 지연 |

## 사무실 배치

- 위쪽 띠는 업무석(책상 줄 2개, 자리 14개), 가운데 복도, 아래쪽은 도서관·인터넷·테스트·회의실·휴게실, 왼쪽 아래가 출입구입니다.
- 업무석 줄을 늘리면 업무석만 아래로 늘어나고 기존 자리 좌표는 그대로입니다(활동 중 자리 재배치 방지).

## 책상 배정(#48)

- 서버가 세션마다 개인 사무실 책상 번호(`desk_slot`)를 배정합니다(`apps/server/src/agent_office/state/desks.py`). 그래서 새로고침하거나 다른 브라우저로 봐도 같은 자리입니다.
- 가장 낮은 빈 번호를 재사용하고, 없을 때만 새 번호를 만듭니다. 종료된 세션의 책상은 퇴근 연출 30초가 지난 뒤에 비워집니다.
- 화면은 번호로 자리를 찾습니다(한 줄 7자리, 열 간격 2칸, 줄 간격 3칸; 서버 `slot_cell`과 같은 규칙). 번호가 늘면 업무석 줄을 늘리고 바닥만 다시 그리며, 캐릭터는 그대로 새 목적지로 걷습니다.
- 1~30 세션에서 번호가 겹치지 않음을 서버 테스트로 확인했습니다. 하위 에이전트는 정규 책상을 받지 않고 대장 옆 칸을 씁니다.
- 외부 에셋 없이 도형으로 그립니다. 스프라이트·Tiled 맵은 #46에서 교체합니다.

## 활동 → 구역

| 사실 상태 | 목적지 |
|---|---|
| `IDLE` | 휴게실 |
| `reading` | 도서관 |
| `browsing` | 인터넷 |
| `testing` | 테스트 구역 |
| `planning` | 회의실 |
| 그 밖(코딩·생각·승인 대기·위임·보고·알 수 없음) | 자기 자리. 하위 에이전트는 대장 옆 칸 |

캐릭터는 출입구에서 나타나 A* 경로로 가구·벽을 피해 걷습니다. 이동 중 목적지가 바뀌면 지금 서 있는 칸에서 다시 경로를 찾습니다(#49). 퇴근·생활 연출은 #50입니다.

## 카메라(#49)

- 드래그·방향키로 이동, 휠·`+`/`−`로 확대(0.5~2.5배). 수동 조작을 하면 자동 초점이 멈춥니다.
- `F` 키나 "자동 초점 다시 켜기" 버튼으로 다시 켭니다. 자동 초점은 유휴가 아닌 캐릭터들의 중심(없으면 사무실 중앙)을 부드럽게 따라갑니다.
- 캔버스는 키보드 포커스를 받을 수 있고(`tabIndex`), 조작 안내 문구를 표시합니다. 이동과 애니메이션은 순수 연출이라 사실 상태를 바꾸지 않습니다.

## 진실성

- 합성 데이터일 때 화면에 항상 "합성 데이터(데모) — 실제 관측이 아닙니다" 배지를 표시합니다(테스트로 확인).
- 합성 진행 함수는 서버 출처 데이터를 거부합니다.
- 로그인 세션이 있으면 서버 실시간 상태를 그리고 "실시간 연결됨/재접속 중" 배지를, 없으면 합성 데이터와 합성 배지를 표시합니다(#47).
- 현재 활동이 추정(`confidence: inferred`)에서 왔으면 캐릭터를 반투명으로 그리고 머리 위에 `?`를 표시합니다. 관측된 승인 대기는 `!`입니다.
- 개발 서버(Vite)는 `/api`를 백엔드로 프록시해(웹소켓 포함) 쿠키·Origin 검사가 같은 출처로 동작합니다. 운영에서는 리버스 프록시가 같은 역할을 합니다(#57).

## 검증과 한계

- Vitest: 투영 왕복, 깊이 순서, 구역별 걷기 가능 칸, 가구·벽 차단, 자리 위치, 업무석 확장 시 기존 자리 유지, 활동 매핑, 하위 에이전트 위치, 종료 세션 미배정, 합성 결정성·출처 표시.
- 실제 브라우저 렌더링(캔버스·FPS)은 Pi에 헤드리스 브라우저가 없어 아직 확인하지 않았습니다. 30캐릭터 30FPS 목표는 #63에서 측정합니다.
