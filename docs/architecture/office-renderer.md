# 사무실 렌더러

관련 이슈: #45~#51

`apps/web/src/office`는 사실 상태를 받아 아이소메트릭 사무실을 그립니다. 논리와 투영, 사실과 연출을 분리합니다.

| 파일 | 역할 | Phaser 의존 |
|---|---|---|
| `types.ts` | 서버 스냅샷·증분(`docs/api/office-live-v1.md`)과 같은 사실 상태 타입, 데이터 출처(`server`/`synthetic`) | 없음 |
| `grid.ts` | 논리 그리드: 구역·가구·벽·출입구·책상 자리, 걷기 가능 판정 | 없음 |
| `iso.ts` | 그리드 ↔ 2:1 아이소메트릭 화면 투영, 깊이 정렬, 타일 마름모 | 없음 |
| `behavior.ts` | 활동 → 목적지 구역, 서버 책상 번호 → 자리, 업무석 줄 수, 목적지 칸 | 없음 |

## 사무실 배치

- 위쪽 띠는 업무석(책상 줄 2개, 자리 14개), 가운데 복도, 아래쪽은 도서관·인터넷·테스트·회의실·휴게실, 왼쪽 아래가 출입구입니다.
- 업무석 줄을 늘리면 업무석만 아래로 늘어나고 기존 자리 좌표는 그대로입니다(활동 중 자리 재배치 방지).

## 책상 배정(#48)

- 서버가 세션마다 개인 사무실 책상 번호(`desk_slot`)를 배정합니다(`apps/server/src/agent_office/state/desks.py`). 그래서 새로고침하거나 다른 브라우저로 봐도 같은 자리입니다.
- 가장 낮은 빈 번호를 재사용하고, 없을 때만 새 번호를 만듭니다. 종료된 세션의 책상은 퇴근 연출 30초가 지난 뒤에 비워집니다.
- 화면은 번호로 자리를 찾습니다(한 줄 7자리, 열 간격 2칸, 줄 간격 3칸; 서버 `slot_cell`과 같은 규칙). 번호가 늘면 업무석 줄을 늘리고 바닥만 다시 그리며, 캐릭터는 그대로 새 목적지로 걷습니다.
- 1~30 세션에서 번호가 겹치지 않음을 서버 테스트로 확인했습니다. 하위 에이전트는 정규 책상을 받지 않고 대장 옆 칸을 씁니다.
- 바닥은 구역 색 마름모, 가구·벽은 그림입니다(아래 "가구·벽 그림"). 캐릭터는 코드로 그린 픽셀 그림입니다.

## 가구·벽 그림(#153)

- 출처: [Kenney Furniture Kit 2.0](https://kenney.nl/assets/furniture-kit), **CC0 1.0**(퍼블릭 도메인, 표기 의무 없음). 사용하는 아이소메트릭 PNG 16장(약 70KiB)만 `apps/web/public/office/kenney/`에 두고 원본 `License.txt`를 함께 둡니다. 새 그림을 넣을 때도 같은 키트(또는 CC0로 확인한 에셋)만 쓰고, `furnitureArt.test.ts`가 파일 목록·라이선스를 검사합니다.
- 배치 데이터는 `apps/web/src/office/furnitureArt.ts`입니다. 논리 그리드(가구 칸은 걸을 수 없음)는 `grid.ts`가 정하고, 칸마다 겹쳐 그릴 그림·위치·층만 정합니다. 배율 0.3은 Kenney 바닥 한 칸(약 208px)을 우리 타일(64px)에 맞춘 값입니다.
- 구역별 가구: 업무석(책상·모니터·사무 의자), 도서관(책장), 인터넷(책상·노트북), 테스트 구역(어둡게 칠한 서버 랙), 회의실(화면·긴 테이블·의자), 휴게실(소파·커피 바·냉장고·화분). 뒤쪽 두 변에는 벽과 창문을 세우고, 출입구·복도 끝은 비웁니다. 벽은 그림 대신 바닥과 같은 2:1 투영으로 직접 그립니다(`walls.ts`). Kenney 렌더 각도(30°)가 바닥과 달라 그림을 이으면 이음매가 어긋났기 때문입니다.
- 그림을 불러오지 못하면 그 그림만 건너뛰고 화면은 계속 동작합니다.

| 사실 상태 | 목적지 |
|---|---|
| `IDLE` | 휴게실 |
| `reading` | 도서관 |
| `browsing` | 인터넷 |
| `testing` | 테스트 구역 |

| 그 밖(코딩·생각·승인 대기·위임·보고·알 수 없음) | 자기 자리. 하위 에이전트는 대장 옆 칸 |

캐릭터는 출입구에서 나타나 A* 경로로 가구·벽을 피해 걷습니다. 이동 중 목적지가 바뀌면 지금 서 있는 칸에서 다시 경로를 찾습니다(#49). 퇴근·생활 연출은 아래와 같습니다.

## 존재 방식과 생활 연출(#50)

| 사실 상태 | 화면 |
|---|---|
| 세션 `ENDED`, 하위 에이전트 `ended_at` 있음, 상태에서 사라짐 | 출입구까지 걸어가 퇴근 후 사라짐. 책상은 서버가 30초 뒤 반납 |
| 장치 `DISCONNECTED` | 퇴근시키지 않고 흐리게(40%), "연결 끊김" 표시 |
| 세션 `UNKNOWN` | 옅게(60%), "마지막 활동 이후 대기" 표시 |
| 추정 활동 | 반투명(55%), `?` |
| `IDLE` | 휴게실에서 8초 주기로 자리를 옮기는 생활 연출(캐릭터마다 시작 시점 엇갈림) |

생활 연출은 사실 상태가 아니며 서버로 보내지 않습니다. 해시는 FNV-1a 후 섞기를 써서 끝 글자만 다른 연속 ID도 고르게 퍼지게 했습니다.

## 카메라(#49)

- 드래그·방향키로 이동, 휠·`+`/`−`로 확대(0.5~2.5배). 수동 조작을 하면 자동 초점이 멈춥니다.
- `F` 키나 "자동 초점 다시 켜기" 버튼으로 다시 켭니다. 자동 초점은 유휴가 아닌 캐릭터들의 중심(없으면 사무실 중앙)을 부드럽게 따라갑니다.
- 캔버스는 키보드 포커스를 받을 수 있고(`tabIndex`), 조작 안내 문구를 표시합니다. 이동과 애니메이션은 순수 연출이라 사실 상태를 바꾸지 않습니다.

## 픽셀 캐릭터(#46)

- 외부 에셋 없이 문자 격자를 2배 픽셀로 텍스처화합니다. 역할·옷 색·프레임 조합마다 한 번만 만듭니다.
- 리드는 왕관과 큰 몸, 하위 에이전트는 작은 몸과 넥타이로 모양부터 다릅니다. 색만으로 의미를 전달하지 않습니다.
- 옷 색은 장치 ID 해시로 정한 8색 중 하나라서 같은 PC의 캐릭터끼리 같고 새로고침해도 유지됩니다. 사용자·팀 구분 색은 팀 사무실(#54·#55)에서 추가합니다.
- 걷는 동안 180ms마다 다리 프레임을 바꾸고 서 있으면 첫 프레임입니다.
- 머리 아래 라벨: 리드는 사용자가 붙인 PC 이름(공백 정리·제어 문자 제거·10자 축약), 하위 에이전트는 "하위". 프롬프트·경로·명령은 서버에 없으므로 라벨에도 나올 수 없습니다.

## 상세 패널(#51)

- 캐릭터를 클릭하면 패널이 열립니다(드래그로 끝난 클릭은 제외). 상위·하위 항목을 눌러 이동하고 Esc나 × 로 닫습니다.
- 기본 정보는 실시간 상태에서 바로 만들고, 서버 모드에서는 선택한 에이전트의 `change_seq`가 바뀔 때마다 `GET /api/v1/office/agents/{id}`로 타임라인·계획 단계를 다시 가져옵니다.
- 합성 데이터에서는 패널에도 합성 표시를 하고 타임라인을 지어내지 않습니다. 추정 상태·추정 이벤트에는 "(추정)"을 붙입니다.
- ID는 서버 ID의 끝 8자만 보여 줍니다. Collector 원본 ID와 원문은 서버에도 없습니다.

## 진실성

- 합성 데이터일 때 화면에 항상 "합성 데이터(데모) — 실제 관측이 아닙니다" 배지를 표시합니다(테스트로 확인).
- 합성 진행 함수는 서버 출처 데이터를 거부합니다.
- 로그인 세션이 있으면 서버 실시간 상태를 그리고 "실시간 연결됨/재접속 중" 배지를, 없으면 합성 데이터와 합성 배지를 표시합니다(#47).
- 현재 활동이 추정(`confidence: inferred`)에서 왔으면 캐릭터를 반투명으로 그리고 머리 위에 `?`를 표시합니다. 관측된 승인 대기는 `!`입니다.
- 개발 서버(Vite)는 `/api`를 백엔드로 프록시해(웹소켓 포함) 쿠키·Origin 검사가 같은 출처로 동작합니다. 운영에서는 리버스 프록시가 같은 역할을 합니다(#57).

## 검증과 한계

- Vitest: 투영 왕복, 깊이 순서, 구역별 걷기 가능 칸, 가구·벽 차단, 자리 위치, 업무석 확장 시 기존 자리 유지, 활동 매핑, 하위 에이전트 위치, 종료 세션 미배정, 합성 결정성·출처 표시.
- 실제 브라우저 렌더링(캔버스·FPS)은 Pi에 헤드리스 브라우저가 없어 아직 확인하지 않았습니다. 30캐릭터 30FPS 목표는 #63에서 측정합니다.
