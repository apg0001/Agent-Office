# 사무실 렌더러

관련 이슈: #45 (후속 #46~#51)

`apps/web/src/office`는 사실 상태를 받아 아이소메트릭 사무실을 그립니다. 논리와 투영, 사실과 연출을 분리합니다.

| 파일 | 역할 | Phaser 의존 |
|---|---|---|
| `types.ts` | 서버 스냅샷·증분(`docs/api/office-live-v1.md`)과 같은 사실 상태 타입, 데이터 출처(`server`/`synthetic`) | 없음 |
| `grid.ts` | 논리 그리드: 구역·가구·벽·출입구·책상 자리, 걷기 가능 판정 | 없음 |
| `iso.ts` | 그리드 ↔ 2:1 아이소메트릭 화면 투영, 깊이 정렬, 타일 마름모 | 없음 |
| `behavior.ts` | 활동 → 목적지 구역, 임시 책상 배정, 목적지 칸 | 없음 |
| `synthetic.ts` | 서버 없이 개발하기 위한 결정적 합성 상태(`source: "synthetic"`) | 없음 |
| `OfficeScene.ts` | Phaser 장면: 바닥·가구·구역 이름 그리기, 매 프레임 캐릭터 이동 | 있음 |
| `OfficeView.tsx` | React 컨테이너. Phaser를 브라우저에서만 지연 로드, 합성 데이터 배지 | 지연 |

## 사무실 배치

- 위쪽 띠는 업무석(책상 줄 2개, 자리 14개), 가운데 복도, 아래쪽은 도서관·인터넷·테스트·회의실·휴게실, 왼쪽 아래가 출입구입니다.
- 업무석 줄을 늘리면 업무석만 아래로 늘어나고 기존 자리 좌표는 그대로입니다(활동 중 자리 재배치 방지, #48에서 확장).
- 외부 에셋 없이 도형으로 그립니다. 스프라이트·Tiled 맵은 #46에서 교체합니다.

## 활동 → 구역

| 사실 상태 | 목적지 |
|---|---|
| `IDLE` | 휴게실 |
| `reading` | 도서관 |
| `browsing` | 인터넷 |
| `testing` | 테스트 구역 |
| `planning` | 회의실 |
| 그 밖(코딩·생각·승인 대기·위임·보고·알 수 없음) | 자기 자리. 하위 에이전트는 대장 옆 칸 |

캐릭터는 출입구에서 나타나 목적지로 걷습니다. 지금은 직선 이동이며 장애물 회피 경로는 #49, 퇴근·생활 연출은 #50입니다. 이동과 애니메이션은 순수 연출이라 사실 상태를 바꾸지 않습니다.

## 진실성

- 합성 데이터일 때 화면에 항상 "합성 데이터(데모) — 실제 관측이 아닙니다" 배지를 표시합니다(테스트로 확인).
- 합성 진행 함수는 서버 출처 데이터를 거부합니다.
- 서버 실시간 연결(`WS /api/v1/live`)은 #47에서 붙입니다.

## 검증과 한계

- Vitest: 투영 왕복, 깊이 순서, 구역별 걷기 가능 칸, 가구·벽 차단, 자리 위치, 업무석 확장 시 기존 자리 유지, 활동 매핑, 하위 에이전트 위치, 종료 세션 미배정, 합성 결정성·출처 표시.
- 실제 브라우저 렌더링(캔버스·FPS)은 Pi에 헤드리스 브라우저가 없어 아직 확인하지 않았습니다. 30캐릭터 30FPS 목표는 #63에서 측정합니다.
